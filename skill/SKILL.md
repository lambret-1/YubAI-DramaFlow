# 🎬 drama-studio — 1 分钟 AI 短剧半自动制片工作流

> **定位**：不产图、不产视频，只产"可直接复制到文生图 / 图生视频 / TTS 工具的提示词包 + 分镜表 + 剪辑清单"。
> **来源**：基于 YubAI-DramaFlow 五阶段方法论，本 Skill 把它压缩为适配"单集 60 秒短剧"的精简流水线。

---

## 0. 硬约束（写死，不可协商）

| 项 | 约束 |
|---|---|
| 单集总时长 | **60 秒**（±3 秒） |
| 段（segment） | 一个场景/情绪单元为一段，**每段 ≤ 15 秒** |
| 每段镜头数 | **5–6 个**镜头（不多不少） |
| 总镜头数 | 4 段 × 5–6 镜 = **20–24 个镜头** |
| 单镜时长 | 2–4 秒（情绪特写可 1.5 秒，动作镜不超过 4 秒） |
| 画面比例 | 默认 **9:16 竖屏**（短剧/漫剧）；用户可改 16:9 |
| 工具调用 | **本 Skill 不调任何图像/视频生成工具**，只产出提示词文档 |

---

## 1. 阶段流水线

```
P1 故事层 ──► P2 风格层 ──► P3 资产层 ──► P4 分镜层 ──► P5 视频提示词 ──► P6 配音配乐
 大纲/剧本    风格锚定词    人物/场景卡     分镜表+静帧提示词  双模板视频提示词    TTS+BGM 清单
   │            │             │               │                 │                  │
  Gate1       Gate2         Gate3           Gate4            Gate5             Gate6
```

每个阶段对应 `phases/p*.md`。**每道 Gate 不过，不进下一阶段。**

---

## 2. 入口路由

用户开口时，先判断他处于哪个入口：

| 用户说 | 进入 |
|---|---|
| "我要做一个 1 分钟短剧，题材是 X" | P1，从 `templates/project-brief.md` 开始 |
| "我已经有剧本了" | 跳过 P1，直接进 P2 |
| "风格定过了，下一步呢" | 读 `project.json`，定位 `current_phase` |
| "继续上次的项目" | 读 `project.json` 续作 |
| "把第 X 镜的视频提示词给我" | 直接读 `storyboard/shots/*.json` 输出 |

## 3. 项目落盘结构（半自动模式）

每个项目在 `projects/<项目名>/` 下生成：

```
projects/<项目名>/
├── project.json                  # 状态机，断点续作用
├── 01_故事/
│   ├── 大纲.md
│   ├── 剧本.md
│   └── 可行性评估.md
├── 02_风格/
│   └── 风格定义.md                 # 含 global_anchor（中英双语 + 负面词）
├── 03_资产/
│   ├── manifest.md               # 资产注册表：中文编码 → 文件路径
│   ├── 人物/<角色名>.md           # 人物卡（含三视图/服装/表情提示词）
│   └── 场景/<场景名>.md
├── 04_分镜/
│   ├── 分镜表.md                   # 人读版
│   └── shots/shot_01.json … shot_22.json   # 机读版，每镜一个
├── 05_视频提示词/
│   ├── 豆包_seedance/shot_XX.txt   # 直接粘到即梦/Seedance
│   └── minimax_h3/shot_XX.txt       # 直接粘到 Hailuo H3 全能参考
└── 06_音频/
    ├── 配音脚本.md                 # 每句台词 → TTS 提示词
    └── 配乐清单.md                 # BGM 情绪 + 时长 + 转场点
```

**关键**：所有图片/视频实际由用户在外部工具跑。本 Skill 只负责"把提示词填到能直接复制"的程度。

## 4. project.json 状态机

```json

  "project_name": "<项目名>",
  "total_duration_sec": 60,
  "ratio": "9:16",
  "current_phase": "p2_style",

    "zh": "...",
    "en": "...",
    "negative": "..."
  }

```

## 5. 双视频提示词模板（P5 核心）

每镜**同时输出两份**提示词，因为豆包（Seedance/即梦）和 MiniMax H3 的提示词语法不同：

| 模板 | 参考文档 | 语法特征 |
|---|---|---|
| **豆包 / Seedance** | `reference/豆包视频提示词模板.md` | `【场景】+【主体】+【动作】+【镜头】+【氛围】+【@引用素材】` |
| **MiniMax H3 多参考** | `reference/minimax-h3-多参考模板.md` | `[Shot N] ... 图1=主角参考, 图2=场景参考, @视频1 节奏参考` |

**图片提示词**（P3/P4 用）统一走 `reference/图片提示词模板.md`（适配即梦/Seedream 官方结构）。

---

## 6. 调用顺序（Agent 必读）

1. 读用户输入 → 判定入口路由
2. 读 / 初始化 `project.json`
3. 进入对应 `phases/p*.md`，按里面的"输入 / 做什么 / 产物 / Gate"执行
4. 每完成一阶段，更新 `project.json.current_phase`
5. 遇到 Gate 不过，**停下来问用户**，不要硬闯
6. P5 必须**逐镜**输出两份提示词文件，不能合并成一段

---

## 7. 与原 YubAI-DramaFlow 的差异

| 原 repo | 本 Skill |
|---|---|
| 五阶段，自由时长 | 压成 6 阶段（多 P6 音频），锁死 60 秒 |
| 模板给人填 | 模板给 LLM 填空，输出直接可复制 |
| 无脚本化 | 每镜一个 JSON，可批量喂外部工具 |
| 工具自由选 | 强制双模板输出（豆包 + H3） |
| 无音频 | P6 单独配音配乐 |
