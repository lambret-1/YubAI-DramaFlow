# P1 故事层 — 从一句话到 4 段短剧剧本

## 输入

- `templates/project-brief.md`（用户先填：项目名 / logline / 基调 / 受众 / 比例 / 时长）
- 用户一句话题材（可与 logline 合并）
- 目标受众 / 基调（以 project-brief 为准，可覆盖）

## 做什么

1. 把一句话扩成 **60 秒大纲**，强制拆成 **4 个 segment**：
   - S1 钩子（0–15s）：抛出冲突/异常
   - S2 发展（15–30s）：冲突升级或反转
   - S3 高潮（30–45s）：情绪峰值
   - S4 收尾（45–60s）：反转/留白/钩子到下集
2. 写剧本：每段只写 **5–6 个 beat**，**1 beat = 1 镜**，每个 beat 一句话动作 + 一句台词/旁白。
3. 逐 beat 标 AI 可行性难度，等级与 `schemas/shot.schema.md` 一致：
   - `green`：单人、固定机位、简单动作，可直接生成
   - `yellow`：轻微运镜、简单交互，可生成但需抽卡
   - `red`：多人、快速动作、复杂运镜，需 fallback
   - `blocked`：打斗、多人混战、精确文字、手部精细动作，必须改写或删除
4. 为每个 segment 指定 **1 个主场景**，全片场景总数 ≤ 4。

## 产物

### 01_故事/大纲.md

- 标题：`# <项目名> — 大纲`
- 全片基调（`tone`）一行
- 四段结构表：段 / 时间 / 内容 / 主场景
- 全片场景数一行

### 01_故事/剧本.md

- 标题：`# <项目名> — 剧本`
- 按段分小节，每段 5–6 个 beat
- 每个 beat 包含：编号 + 一句话动作描述 + 难度标记（🟢/🟡/🔴/⛔）+ 台词/旁白（如有）

### 01_故事/可行性评估.md

- 标题：统一 `# AI 可行性评估`
- **场景统计**：场景总数、是否符合 ≤4 约束
- **逐 beat 难度表**：`Beat | 人物数 | 动作 | 运镜 | 难度`，全片每个 beat 一行
- **汇总统计**：
  - 🟢 低难度数量及占比
  - 🟡 中难度数量及占比
  - 🔴 高难度（含⛔）数量及占比
  - 主角单人镜头占比
  - 高难度镜头占比
- **风险点**：逐条列出高难度 beat 的具体问题 + 改方案
- **结论**：`结论：可进入 P2。` 或说明需修改项

### 01_故事/场景清单.md

- 每个场景的编码（`<场景名>_<时段>`）、出现段、用途，供 P3 建场景卡

## Gate1（不过不进 P2）

- [ ] 恰好 4 个 segment，每段 15s，总 60s
- [ ] 每段 5–6 个 beat，1 beat = 1 镜
- [ ] 主角单人镜头占比 > 60%
- [ ] `red` + `blocked` 镜头总数 ≤ 3 个（占比 < 15%）
- [ ] 无“打斗、多人混战、精确文字、手部精细动作”等 `blocked` 元素（或已改写为替代）
- [ ] 场景总数 ≤ 4 个（每个 segment 一个主场景）
- [ ] `01_故事/场景清单.md` 已输出，场景编码符合 `<场景名>_<时段>`
- [ ] `01_故事/大纲.md` 已写明全片基调（`tone`），供 P2 使用
- [ ] `01_故事/可行性评估.md` 包含场景统计、逐 beat 难度表、汇总统计、风险点、结论五部分
